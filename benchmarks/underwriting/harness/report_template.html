The Cost of a Correct Underwriting Decision

We gave twelve models the same underwriting copilot job: talk to an underwriter, look up the insurer's classification codes, size rules and appetite guide, and decide. Across 252 real-shaped cases, the best model was not the most expensive, the most expensive was not the best, and the cost of a correct decision varied about forty-fold.

Update: a second run tuned each model's prompt on separate learning cases, and on held-out cases the gaps mostly closed, with one shared prompt doing as well as per-model tuning; see "Then we tuned the prompt" and "One prompt for everyone". 252 tasks × 12 models, one run each. Reference for comparisons: Claude Opus 5.5. Costs at list prices, including every model call the copilot made.

Findings

  1. The top is a tie, and an open model is in it. DeepSeek V4 Pro and Claude Opus 5.5 are statistically indistinguishable (+0.4 points, 95% CI −2.0 to +2.8). DeepSeek costs 3.55¢ per correct decision, Opus 5.26¢. A team that can host or buy open-weight inference does not give up accuracy here.
  2. Price is not quality. GLM 5.3 is the most expensive model per correct decision (8.25¢) because it spends many tokens, yet it is 2.4 points behind Opus. Sonnet 5.5 costs less than Opus per task but is 8.3 points worse. Opus works in fewer steps than any other model (6.5 calls and about 25k tokens per case), which is why it is cheaper per correct decision than its list price suggests.
  3. Cheap models fail on specific question types, not uniformly. Policy limits need the written guidelines applied to the company's numbers; GLM 5.3, GLM 5.3 Flash and MiniMax-M3 get 65% of them right and DeepSeek V4.1 Flash 53%, while DeepSeek V4 Pro and Sonnet 5.5 get 94% (only 17 such cases, so treat the size of the gap loosely). Product recommendations (which other lines are in appetite) are where Sonnet 5.5 (78%), MiniMax-M3 (75%) and Qwen3.8 27B (67%) lose most of their points. Averages hide this; a per-type table does not.
  4. Some failures are about the agent loop, not knowledge. GPT-6.1 Sol often ends the case with a final answer that is actually a question to the underwriter, so its appetite checks are only 71% correct. gpt-oss-120b emits malformed tool calls (28 times). Qwen3.8 27B runs out of steps on 17 cases. Each would look different with a different harness; that is part of the result, because the harness is part of the system you deploy.
  5. No sign the models memorized the public answers. Without the insurer's data, no model named the right set of other in-appetite products (@@probe_products@@ answers). On appetite checks, models were right @@probe_app@@ times, consistent with reasoning about fire risk for a few business types rather than recall.

Then we tuned the prompt

The first run gave every model the same system prompt. We then split the cases into 84 for learning and 168 held out, let Claude Opus 5.5 rewrite each model's prompt from its failures on the learning cases only (general instructions, no case facts), and scored the best prompt once on the held-out cases.

Held-out cases only, paired against each model's original run on the same cases. Sonnet 5.5 rerun with the original prompt moved +2.4 points [−3.6, +8.3], which is the noise floor. GPT-6 Luna was not tuned: no rewrite beat its 78 of 84 learning cases.

Tuned, six models land within about two points of each other, inside the noise. The first ranking was largely a ranking of how well each model coped with an under-specified prompt. At that tier the cheapest model is Claude Haiku 5.5 at 0.38¢ per correct decision, about eleven times cheaper than tuned Opus 5.5. For the model in use today, Sonnet 5.5, the rewrite gained ten points and cut cost per correct decision by a third: more than any model swap in the first run. Effort settings moved less: high reasoning effort helped GPT-6.1 Sol (+9.5), and lower effort hurt Sonnet 5.5 (−16.7 at low).

The rewrites changed conversation and answer discipline, not facts: ask which line of business the application is for, classify the business from the database and treat it as settled, commit to one answer, never end on a question, answer only what was asked. Judges agreed more often on tuned answers, so the answers got clearer rather than easier to grade.

One good prompt lifts nearly everyone. Ten of eleven models gained, and nine land between 97.6% and 99.4%, within noise of each other; giving each model its own tuned prompt added nothing measurable. With accuracy a near tie, the choice is cost: Claude Haiku 5.5 (98.8% at 0.38¢ per correct decision) and GLM 5.3 Flash (99.4% at 0.92¢) lead, and Opus 5.5 costs about thirteen times as much as Haiku per correct decision for no measurable gain. GPT-6 Luna and Qwen3.8 27B do not catch up.

Method

Tasks. Snorkel AI's public multi-turn insurance underwriting datasets (Apache-2.0): an underwriter asks a copilot about a small business (appetite for a line of business, other products to offer, small-business eligibility, policy limits, deductibles, NAICS classification). We rebuilt the insurer's environment the agent queries: NAICS 2022 codes and Census concordances, the SBA size-standard table, the appetite guide and the underwriting guidelines, recovered from the published traces. A rule-based oracle re-derives each reference answer from that environment; we kept the 252 of 380 tasks where it agrees, so every scored task is answerable from the data the agent can see.

Agent. Every model gets the same system prompt and six tools over a SQLite database, and talks to a simulated underwriter (Claude Haiku 5.5) that knows the company profile but not the answer. The case ends when the copilot writes "FINAL ANSWER:", or after 30 model calls or 12 underwriter turns.

Grading. Two LLM judges (GPT-6 Luna and Claude Haiku 5.5) compare the final answer to the reference; GPT-6.1 Sol breaks ties. On Snorkel's own labeled traces the judges agree with the human labels 87–90% of the time.

Statistics. Wilson 95% intervals for accuracy; paired bootstrap (4,000 resamples) for differences against Opus 5.5, on the same 252 tasks for every model.

Caveats

  • One run per task per model; differences under about 3 points are inside the noise.
  • The environment is a reconstruction; a third of the original tasks were dropped where it disagreed with the reference.
  • The underwriter is simulated and the grading is by LLM judges, both validated but not perfect.
  • List prices; open-weight models were served by a commercial inference provider, and prices and speed vary across providers. Latency is end-to-end and includes the simulator.
  • The datasets are public, so contamination is possible; the probe above found no sign of it.
